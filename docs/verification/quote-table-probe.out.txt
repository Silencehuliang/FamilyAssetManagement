SQLITE_VERSION   = 3.53.1
股价/市值单位    = 整数「分」（价格存「分/股」）

时间口径         = 交易日日期为东八区日历日（文本 YYYY-MM-DD），无时区换算
实测样本         = 贵州茅台 sh600519，除权除息日 2026-06-26

[1] 除权除息日：「昨收」怎么来，决定当日盈亏是 −15.45 还是 −43.47
==============================================================================
  前一日（2026-06-25）原始收盘      = 1,212.10 元
  除权日（2026-06-26）原始收盘      = 1,168.63 元
  每股派息                  = 28.02423 元（= 2802 分，按分取整）
  交易所除权(息)参考价      = 1,212.10 − 28.02 = 1,184.08 元
  当日 feed 返回的「昨收」  = 1,184.08 元   ✔ 与参考价吻合

  路径   口径                             存入的昨收   存入的收盘     当日盈亏 判定
  A      存不复权 ＋ 采信 feed 昨收         1,184.08     1,168.63       -15.45 ✔ 正确
  B      存不复权 ＋ 从本地上一行推算昨收     1,212.10     1,168.63       -43.47 ✘ 假暴跌
  C      存前复权 ＋ 逐日抓取冻结           1,212.10     1,168.63       -43.47 ✘ 假暴跌

  → 路径 B 与 C 收敛到同一个数 -43.47 元，与正确的 -15.45 元相差 28.02 元/股，
    差额恰好等于每股派息 28.02 元 —— 已经落袋的那部分被记成了亏损。
  → 且路径 A 用的昨收与「前复权序列的前一日收盘」逐分吻合：
      fqt=1 在 2026-06-25 的收盘 = 1184.08 元 = feed 昨收 1184.08 元
    ⇒ **回填时昨收可被精确还原**，无需留空（见第 3 节）。

[2] 前复权基准随每次分红整体平移 ⇒ 逐日存下的行各自冻结在不同基准上
==============================================================================
  刚性证据一：同一历史日期、不同请求窗口下，fqt=1 的值完全相同；
  但 preKPrice（窗口首根前一日收盘）却随窗口变化 —— 说明基准是「拉取当日的最新日」，不是窗口：
  请求窗口                   fqt=0 preK     fqt=1 preK       两者差
  20260601-20260624            1,326.00       1,297.98        28.02
  20260618-20260702            1,240.00       1,211.98        28.02
  两个窗口的差都是 28.02 元 —— 与「拉取当日」无关的那次分红，被整体平移到了所有历史行上。

  刚性证据二：把「逐日抓取到的前复权值」按日存进同一张表，会发生什么：

  日期           抓取时点         当日基准           存下的前复权值
  2026-06-24     06-24 盘后       分红尚未发生             1,207.68
  2026-06-25     06-25 盘后       分红尚未发生             1,212.10
  2026-06-26     06-26 盘后       分红已发生               1,168.63

  表内相邻两行                 存下的差       真实的差 判定
  06-24 → 06-25                    4.42           4.42 ✔ 一致
  06-25 → 06-26                  -43.47         -15.45 ✘ 凭空少掉一次分红

  → 全区间累计：存下来的 1,168.63 − 1,207.68 = -39.05 元；真实累计 = -11.03 元；
    凭空多出 28.02 元亏损。**前复权价不能逐日冻结入库。**

[3] 回填请求数：与回填深度 M 无关，只与只数 N 成正比（票面前提已修正）
==============================================================================
  实测：一次区间请求返回 dktotal = 6005 根日线（≈ 24.6 年），beg/end 只是参数。
  ⇒ 回填 3 年与回填 1 天，成本完全相同；不存在「N 只 × M 天」这个乘积。

    回填只数 N  补齐 close+prev_close       只补 close 是否超 50 上限   备注
             5                     10                5 否               
            10                     20               10 否               
            20                     40               20 否               
            25                     50               25 否               恰好用满 50
            30                     60               30 是               
            50                    100               50 是               必须分批

  对照：若票面的「N 只 × M 天」成立，20 只 × 250 天 = 5,000 请求，
        是本设计（20 只 = 40 请求）的 125 倍。
  → 单次运行设「最多 10 只缺口」上限 ⇒ 20 个子请求，留足余量给当日行情抓取。

[4] 区间收益：端点口径（期末市值−期初市值）在缺口下仍然正确，Σ 可得日会低估
==============================================================================
  日期             数量       昨收       收盘     当日盈亏 区间归属
  2026-09-07        100       9.90      10.00        10.00 期初日，其盈亏归**上一**区间
  2026-09-08        100      10.00      10.10        10.00 计入本区间
  2026-09-10        100      10.40      10.50        10.00 计入本区间
  2026-09-11        100      10.50      10.60        10.00 计入本区间
  2026-09-09        100          —          —     无行情行 **无法计入**

  口径 A（推荐）端点法：期末市值 − 期初市值 = 1,060.00 − 1,000.00 = 60.00 元
  口径 B（Σ 可得日）      ：30.00 元

  → 分岔 = 30.00 元，恰好等于缺口当日「收盘 1040 − 昨收 1010」× 100 股 = 30.00 元。
  → 真实总涨跌 = 1060 − 1000 = 60 分/股 × 100 股 = 60.00 元 ⇒ **端点法准确，Σ法静默低估**。
  → 故「恒等于」只在无缺口时成立；有缺口时以端点法为权威，并显式提示缺口天数。

  ⚠️ **差一错陷阱（本脚本第一版就踩了）**：期初市值取自**期初日收盘**，
     因此期初日自己的「当日盈亏」属于**上一个**区间，必须排除在本区间之外——
     否则每个区间都会多算一天（本例会把 Σ 从 30.00 元算成 40.00 元，分岔伪装成 20.00 元）。
     实现里必须把这条口径写死在一处，不得各处各自解释。

[5] 每股派息 28.02423 元 —— 分/股与厘/股都不够，必须微元/股
==============================================================================
  存储单位                 折算每股     持有 1000 股的分红     与真实值之差
  分/股 (1e-2)                28.02               28020 元         -4.23 元
  厘/股 (1e-3)               28.024               28024 元         -0.23 元
  微元/股 (1e-6)           28.02423            28024.23 元             0 元

  → 参考价按分取整（1,184.08 元）不受影响；受影响的是「提示成员的分红金额」。
  → 微元不增加任何复杂度（仍是一个 INTEGER 列），却把这类失真归零。

[6] 防护：行情源返回「最新价 = 0」时照单入库 ⇒ 凭空一条 −100% 的暴跌
==============================================================================
  构造：昨收 12.34 元、最新价返回 0、持仓 1,000 股
  若照单入库：当日盈亏 = (0 − 12.34) × 1000 = -12,340.00 元 ⇒ 该股当日收益率 -100.00%
  正确处理：判为解析失败 ⇒ **不落行**，该日无行情，不计入分母、不画点。
  依据：调研记录明确「盘后/休市时部分源返回最新价 0 」⇒ 0 是**无效标记**，不是价格。

[7] 缺口 = 行情源返回的日期 − 我方已有的日期（差集）；非交易日天然被排除
==============================================================================
  我方 quote_daily 已有：2026-09-08  2026-09-09  2026-09-11
  行情源返回的日期   ：2026-09-08  2026-09-09  2026-09-10  2026-09-11

  差集（= 缺口）     ：2026-09-10
  缺口天数           ：1

  非交易日为何不会误判：非交易日**根本不在源返回的日期序列里**（如 09-12 周六），
  故差集不可能包含它 ⇒ **系统无需自建、也无需维护交易日历表**。
  检测与补数共用同一次请求：源返回的日期序列既定义交易日，又直接给出待补的收盘价。

[8] quote_daily：主键查询走索引；CHECK 与主键冲突按预期拒绝
==============================================================================
  某只股某区间取数                  → SEARCH quote_daily USING INDEX sqlite_autoindex_quote_daily_1 (code=? AND trade_date>? AND trade_date<?)
  某日全部持仓取数（一条 SQL 覆盖） → SEARCH quote_daily USING INDEX sqlite_autoindex_quote_daily_1 (code=? AND trade_date=?)
  → 两条查询都命中 PRIMARY KEY；无需为日期维度另建二级索引。

  场景                               结果       说明
  feed 行缺 prev_close               拒绝       CHECK constraint failed: source = 'manual' OR prev_close IS NOT NULL
  前缀不合法（不带 sh/sz）           拒绝       CHECK constraint failed: code LIKE 'sh%' OR code LIKE 'sz%'
  重复的 (code, trade_date)          拒绝       UNIQUE constraint failed: quote_daily.code, quote_daily.trade_date
  manual 行缺 prev_close（应通过）   接受       符合预期

  → `CHECK (source = 'manual' OR prev_close IS NOT NULL)` 把「非手工行缺昨收」
    这类解析失败挡在库外 —— 否则它会以「昨收 = 0」的形态静默污染收益。

[9] corporate_action：同一次分红，两位成员各自确认一次；重复检测天然幂等
==============================================================================
  写入成员 1 的待确认建议：10派280.2423元(含税) → status = pending
  同一事件重复检测第二次              → 拒绝：UNIQUE constraint failed: corporate_action.member_id, corporate_action.code, corporate_action.ex_date

    成员 代码         除权日         状态           决策时刻
       1 sh600519     2026-06-26     applied      1789000000
       2 sh600519     2026-06-26     pending               —

  → 成员 1 已采纳、成员 2 仍待确认 ⇒ 状态必须按 (成员, 代码, 除权日) 记，不能按股记。

结论
==============================================================================
1. 存**不复权**价、`prev_close` **逐行取自行情源**：当日盈亏 -15.45 元/股。
   从本地推算昨收、或逐日冻结前复权价，两条错误路径都给出 -43.47 元/股（差一次分红）。
2. 前复权序列的**逐日差额**等于真实盈亏，但其**基准随每次分红整体平移** ⇒
   只能用于「回填时反推昨收」，**不能作为存储口径**。
3. 回填请求数 = 1~2 × 只数，**与回填深度无关**；一次请求即可返回该股全部历史日线。
4. 区间收益以**端点法**为权威；Σ 可得日在有缺口时静默低估（本例漏掉 30.00 元）。
   且**期初日的当日盈亏归上一区间**，实现里必须写死这一条，否则每区间多算一天。
5. 派息必须用**微元/股**（分与厘都会失真）；`最新价 == 0` 必须判为解析失败。
6. 缺口检测 = **差集**，交易日历由行情源自带 ⇒ 系统不建、也不维护交易日历表。
