§6 PRAGMA defer_foreign_keys 的必要性 —— 真跑（#14 说它是「必需品」，此处实测）
==============================================================================
  模拟 D1：D1 恒为 PRAGMA foreign_keys = ON，且用户查询无法关闭。
  PASS  §6.1 逆序导入、不开 defer -> 被外键拒绝  |  FOREIGN KEY constraint failed
  PASS  §6.2 按依赖序导入 -> 成功（官方 Troubleshooting 的「right order」）  |  1
  PASS  §6.3 开 defer + 同事务内修复 -> 逆序导入成功  |  1
  PASS  §6.4 defer 只在**当前事务**内有效：离开事务仍未修复 -> 失败  |  FOREIGN KEY constraint failed
  PASS  §6.5 defer 孤零零地写在一条语句里、违规写在**下一条** -> 无效（这是自建多语句导入的陷阱）  |  FOREIGN KEY constraint failed

  结论：官方导入章节只指定 defer_foreign_keys 是**对的**，但它要求「同一事务内修复」；
        因此自建多语句回导必须把全部语句挤进**一个 batch()**，而这正是不做站内导入的技术理由。
