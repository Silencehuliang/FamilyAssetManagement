[0] 环境
==============================================================================
SQLITE_VERSION      = 3.53.1
本机 Python 时区     = 中国标准时间
zoneinfo Asia/Shanghai = 不可用（ZoneInfoNotFoundError）

为何不依赖 IANA 时区库：中国自 1986–1991 年试行夏时制，1992-04-05 国务院决定暂停，
此后全国全年恒为 UTC+8，无任何时区偏移变动。
  来源：新华网《夏时制：节能还是“添乱”》https://www.xinhuanet.com/world/2015-06/10/c_1115566756_3.htm
  来源：Time in China, Wikipedia — “Daylight saving time has not been observed since 1991.”
  → 固定 +8 偏移在**本系统全部数据**上精确成立（系统全新开始，不导入 1991 年前的历史）。
  → 生产实现因此**不需要** IANA tz 数据（本机 zoneinfo 缺 tzdata 包也不构成风险）。
    该结论为时效性事实，检索口径 2026-09-15。

SQLite 侧时区行为（同一条 SQL 在本机 vs 在 D1 的含义）：
  datetime('now')                -> 2026-09-15 08:11:54
  datetime('now','localtime')    -> 2026-09-15 16:11:54
  unixepoch('now')               -> 1789459914
  ※ 本机 OS 时区是东八区，故 localtime 给出 CST；D1 上它等于 UTC（空操作）。
  ※ 结论：周期边界必须在应用层算成 UTC 区间后传参，SQL 内禁用 localtime。

[2] 正确做法：应用层算周期边界 → UTC 区间 → SQL 整数区间查询
==============================================================================

  周报触发：2026-09-21(周一) 08:00 CST
    周期键          = 2026-W38
    覆盖 CST 区间   = [2026-09-14 00:00, 2026-09-21 00:00)
    等价 UTC 区间   = [1789315200, 1789920000)  (2026-09-13 16:00Z ~ 2026-09-20 16:00Z)
    该窗口支出合计  = 900.00 元（单条 SQL，无时区函数）

  月报触发：2026-10-01 08:00 CST
    周期键          = 2026-09
    覆盖 CST 区间   = [2026-09-01 00:00, 2026-10-01 00:00)
    等价 UTC 区间   = [1788192000, 1790784000)  (2026-08-31 16:00Z ~ 2026-09-30 16:00Z)
    该窗口支出合计  = 1000.00 元（单条 SQL，无时区函数）

[4] Cron 表达式换算（Cloudflare 恒按 UTC 执行；星期编号 1=周日 … 7=周六）
==============================================================================
  行情抓取         30 7 * * MON-FRI       期望 CST 15:30 交易日
  预算提醒巡检       0 12 * * *             期望 CST 20:00 每日
  周报推送         0 0 * * MON            期望 CST 周一 08:00
  月报推送         10 0 1 * *             期望 CST 每月 1 日 08:10

  扫描区间：2026-09-15 00:00Z ~ 2027-12-31 00:00Z（UTC 分钟粒度）

  行情抓取（30 7 * * MON-FRI）共触发 338 次，最近 3 次（CST）：
    2026-09-15 07:30 UTC → 2026-09-15 15:30 Tue CST
    2026-09-16 07:30 UTC → 2026-09-16 15:30 Wed CST
    2026-09-17 07:30 UTC → 2026-09-17 15:30 Thu CST

  预算提醒巡检（0 12 * * *）共触发 472 次，最近 3 次（CST）：
    2026-09-15 12:00 UTC → 2026-09-15 20:00 Tue CST
    2026-09-16 12:00 UTC → 2026-09-16 20:00 Wed CST
    2026-09-17 12:00 UTC → 2026-09-17 20:00 Thu CST

  周报推送（0 0 * * MON）共触发 67 次，最近 3 次（CST）：
    2026-09-21 00:00 UTC → 2026-09-21 08:00 Mon CST
    2026-09-28 00:00 UTC → 2026-09-28 08:00 Mon CST
    2026-10-05 00:00 UTC → 2026-10-05 08:00 Mon CST

  月报推送（10 0 1 * *）共触发 15 次，最近 3 次（CST）：
    2026-10-01 00:10 UTC → 2026-10-01 08:10 Thu CST
    2026-11-01 00:10 UTC → 2026-11-01 08:10 Sun CST
    2026-12-01 00:10 UTC → 2026-12-01 08:10 Tue CST

  同一天多个任务撞车检查（同一 Worker 多 cron 的并发语义官方未说明，故须错开）：
  判定口径：同一条 UTC 分钟即视为撞车；仅同一天不算。
    无任何一条 UTC 分钟出现两个任务 —— 四个时点两两不重叠，并发风险归零。

  同日多任务情形（非并发，仅提示一天内触发次数）：

    2026-09-16   行情抓取@15:30 / 预算提醒巡检@20:00

  配额占用 = 4 / 5（Workers Free，账户级上限）

结论：周期边界必须由应用层按 Asia/Shanghai 算成 UTC 区间；
      UTC 天真分组会把 CST 00:00–08:00 的支出错记到前一日，进而错位到上一周期。
