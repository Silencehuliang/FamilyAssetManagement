## 2. 导航壳（Q1 决议）

### 2.1 定型

```
┌──────────────────────────────────────────────┐
│  [头像]  首页 · 2026-09（CST 自然月）   [在线] │  ← 头像点开 = 我的
│  ─────────────────────────────────────────  │
│  全局横幅（条件渲染，见 §9）                  │
│  全局「待同步 N 条 ›」（条件渲染，任一页可见） │
│  ─────────────────────────────────────────  │
│                页面内容                       │
│  ─────────────────────────────────────────  │
│   首页    流水    (＋)    股票                │  ← 四 Tab，中央凸起
└──────────────────────────────────────────────┘
```

- **Tab 集合**：`home` / `ledger` / `entry` / `stock`，**恰好四个**。
- **「我的」（`me`）不是 Tab**：入口是首页右上角头像，深度 2 步。
- **「＋」是中央凸起按钮**，视觉上高于其余三个 Tab，且**在两个子系统之间居中** —— 两个子系统各占一个 Tab，不共用一个容器。

### 2.2 被否选项及理由

| 被否 | 理由 |
|---|---|
| **A 原版五 Tab** | 原型里的 A 是五 Tab（首页 / 流水 / 记一笔 / 股票 / **我的**）。实测步数不劣，但「我的」是设置类低频页，占用底栏 1/5 面积而使用频次远低于其余四格 ⇒ 精剪掉。<br>⚠️ **口径说明**：Q1 的四个候选项来自原型内的 A/B/C/D，而原型 A 是五 Tab；本决议 = 「原型 A 减掉『我的』这一格」，**不是原型 A 原样**。 |
| **B 四 Tab + 分段** | 把两个子系统塞进「资产」一个 Tab，靠分段控件切。代价有二：① 首页→股票**从 1 步变 2 步**；② 分段状态需被记忆（原型 `assets` 页自陈此代价）。两个子系统在本项目里是**平级**的，用容器收纳等于人为降级其一。 |
| **C 三 Tab 首页聚合** | 首页信息密度最高，但**「记完立刻看流水」从 1 步变 2 步**。而「记一笔 → 立刻核对刚记的这笔」是本系统**最高频的连续动作**（用户口径：快速记账是最核心诉求）。让最高频路径为「首页好看」付一步，代价方向反了。 |
| **D 抽屉菜单** | 所有页面藏进汉堡：首页→记一笔 **从 2 步变 3 步**；且**没有底栏 ⇒ 全局「待同步」指示器失去常驻位置**，与 #10 派生要求 1（全局待同步指示器）直接冲突。 |

### 2.3 实测事实（可复跑）

步数度量由原型内 BFS 从导航图算出，口径：**一次点击 = 1 步（不含键盘输入）；「保存」本身计 1 步**。
复跑：`node docs/verification/frontend-ia-proto-check.js`（输出 `.out.txt` 第 2 节）。

| 变体 | 首页→记账→保存 | 记完→看流水 | 首页→股票 | 最坏路径→保存 |
|---|---|---|---|---|
| **A 五 Tab 平铺** | 2 步 | 1 步 | 1 步 | 3 步（从 expense） |
| **B 四 Tab + 分段** | 2 步 | 1 步 | **2 步** | 3 步（从 expense） |
| **C 三 Tab 首页聚合** | 2 步 | **2 步** | 1 步 | 3 步（从 ledger） |
| **D 抽屉菜单** | **3 步** | 2 步 | **2 步** | 3 步（从 home） |

**度量结论**：导航深度差异整体**只差 ≤1 步**，单看步数不足以选型。真正**不可兼得**的是「记完看流水」与「看股票」两条路径：B 让股票多一步，C 让看流水多一步，**A 在两条路径上均不劣**，D 在两条上都劣。⇒ 选型由「哪条路径被牺牲」决定，A 是唯一不牺牲任何一条的形态。

**A 精剪相对原型 A 的唯一变化**：`me` 从 1 步（Tab）变 **2 步**（首页 → 头像）。上表三条被度量路径均不经过 `me`，故**度量结论不受影响**。`me` 是设置类低频页，深度 2 步可接受（§12 列为已知代价）。

## 3. 页面清单（Q2 决议）

### 3.1 完整清单 —— 12 页

| # | 路由键 | 页面名 | 底栏 Tab | 从首页的步数 | 离线可用性 |
|---|---|---|---|---|---|
| 1 | `login` | 登录 | — | 未认证入口 | 需在线 |
| 2 | `home` | 首页 | ✅ | 0 | 只读降级 |
| 3 | `ledger` | 流水 | ✅ | 1 | 只读降级（缓存 ∪ 队列合并） |
| 4 | `entry` | 记一笔 | ✅（凸起） | 1 | **完整可用**（唯一可离线写入） |
| 5 | `stock` | 股票持仓 | ✅ | 1 | 只读降级（双时间戳） |
| 6 | `expense` | 支出分析 | — | 2 | 离线不可用 |
| 7 | `budget` | 预算 | — | 2 | 离线不可用 |
| 8 | `trend` | 收益趋势 | — | 2 | 离线不可用 |
| 9 | `ca` | 除权确认 | — | 2（经股票页） | 离线不可用 |
| 10 | `tags` | 标签管理 | — | 2 | 离线不可用 |
| 11 | `queue` | 待同步 | — | 1（全局指示器） | 本页即离线态 |
| 12 | `me` | 设置 / 我的 | — | 2（首页头像） | 离线不可用 |

**⚠️ 口径修正（本票自查发现）**：原型内共 13 个页面键，其中 `assets`（资产）**是变体 B 独有的产物** —— 只有「把两个子系统收进一个 Tab」才需要那个分段容器。Q1 选定 A 之后，`assets` 失去存在理由，**不进入最终清单**。
因此「13 页」是**原型覆盖面**，**「12 页」是定型清单**。Q2 的「不合并」决议针对的是 **除权确认**与**待同步**这两处（见 3.3），不包含保住 `assets`。

### 3.2 每页核心信息与主操作

**① 登录（`login`）** —— 唯一未认证页面
- 核心信息：标题「家庭财务」+ 用户名 + 密码。
- 主操作：登录。
- 硬约束：**没有注册入口**（`/api/register` 端点不存在，不是被禁用）；失败固定延迟 500ms、不区分「用户不存在」与「密码错」；须说明「首次在 PWA 里打开要登录一次」（与 Safari 是两套隔离数据容器，#9）。

**② 首页（`home`）**
- 核心信息：成员名 + 当期（CST 自然月）→ 本月总支出 → **预算进度条**（含 80% / 100% 两条阈值线）→ **类别 Top 5 条形**（按当前标签基线实时聚合）→ 页面入口宫格 → **运行状态卡**。
- 主操作：点头像进「我的」；点宫格进二级页；点状态卡看心跳详情。
- 关键约束：运行状态卡的「上次成功运行」取自 `cron_run`，**必须按 `task` 分别问**（行情与除权是同一 `scheduled_at` 下的两行心跳），**不得取全局最大**；该表 `scheduled_at` 是 UTC 毫秒、其余时间列是 UTC 秒，**格式化不要一把梭**。
- 离线态：汇总只显示缓存值，**队列项不计入**，显式标注「离线时汇总只显示缓存值，队列项不计入 —— 不复刻服务端聚合口径」。

**③ 流水（`ledger`）**
- 核心信息：筛选条（成员 / 区间 / 类别）→ 倒序分页列表，每行 = 日期 · 类别 · 对象 · 金额 ·（同步徽标）。
- 主操作：点行 → 详情 / 编辑 / 删除（**在线才可**）。
- 关键约束：按成员 + 区间倒序分页走 `ix_entry_member_date`，**已索引**。⚠️ 若要加「按标签筛选 + 分页」这类**组合筛选**，须把查询形态带回 #14 —— 索引是按已列出的查询方向建的。
- 三种同步徽标必须可区分：`待同步`（未提交）/ `同步失败`（提交被拒，附原因）/ `长期未同步`（>7 天）。

**④ 记一笔（`entry`）** —— 最高频页
- 字段序：金额 → 类别（必填单值）→ 对象（≤4）→ 谁花的 → 发生时间 → 备注 → 本地模板 → 常用标签置顶 → 保存。
- **金额输入框：`type="text"` + `inputmode="decimal"`，不用 `type="number"`**（后者忽略 `pattern`、`step` 默认 1、允许 `e`/`+`/`-`）；解析**用字符串算整数分**，**禁用 `parseFloat(x)*100`**，且**同时接受 `.` 与 `,`**（WebKit bug 247242 仍 NEW）。
- 「谁花的」默认值 = `GET /api/session` 返回的成员；**不支持代记**（录入者恒等于归属成员）。
- 发生时间默认现在，**不可指向未来**；补记不设上限；`biz_date` 由 CST 换算，趋势轴按它分组。
- 类别选项只列默认集 5 个（餐饮 / 住房 / 出行 / 医疗 / 其他，**完全不可变**）+ 自建标签 + 模板包导入物；**不做标签自动补全输入框**（标签集只有几十个，下拉比打字快）。
- **本地模板**存于设备侧 IndexedDB，**不进备份**，一键预填但**仍需手动确认**（替代被排除的服务端「定期消费」规则）。
- 幂等键 `client_ref` **在打开本表单时生成一次**，重试复用同值 —— 在线同样需要（「点保存 → 超时 → 再点一次」的重复风险不是离线专属）。
- 离线态：入队列；**超 5 分钟容差的未来时间会被拒并标红，不静默改写**。

**⑤ 股票持仓（`stock`）**
- 核心信息（自上而下）：成员分段（全部 / 逐成员）→ **行情缺口提示条** → **除权建议** → 持仓表 → **未交易金额** → 登记入口。
- 持仓表列：代码 / 数量 / 成本价 / 最新价 / 市值 / **累计浮盈**。**本页无任何图表**（Q4 决议）。
- 除权建议**必须分开说两类成分**：送转 → 需确认后落新版本；现金分红 → 只提示不写库（红利税）。文案须含「**采纳只解决送转那一半**」。
- 缺口提示条的**次序固定为「补数在前、手工录价在后」** —— 因为手工行会被权威源覆盖并升级来源。
- 离线态：整页只读降级，**双时间戳缺一不可**：「行情截至 YYYY-MM-DD」+「缓存于 YYYY-MM-DD HH:mm」。只给数据日期会以为是刚拉的，只给缓存时刻会以为是实时价。
- 登记入口离线置灰，且**说明原因**（不是只灰不说）。

**⑥ 支出分析（`expense`）**
- 核心信息：分组轴分段控件（**按类别 / 按对象 / 按时间趋势，三选一**）× **成员固定 2 列** + 筛选 + 数据表 + 图表 + 上期对比 + 下钻。
- **不做多维矩阵**（#4 冻结）。
- 表格必须含虚拟行「**未细分**」与「**未指定对象**」桶：前者保证「展开后子项之和 = 父项」，后者显式列出未打对象标签的那部分。
- 上期对比：**上期无数据时不给变化率**，显示「无上期数据」，**不以 0 或 100% 代替**。
- 键约束：每个分析视图 **≤ 5 条 SQL**；全实时聚合、无汇总表。
- 离线不可用，须说明原因「筛选组合开放，缓存必然大量未命中」。

**⑦ 预算（`budget`）**
- 核心信息：**家庭总预算**（至多一条，口径 = 总支出）→ **按标签的预算列表**（父 = 子树合计）→ 变更入口。
- 每条预算显示「已用 / 上限」+ 消耗百分比 + 档位徽标（正常 / 预警 ≥ 阈值 / **超支 > 上限**）。
- 须显式说明：**「子超支、父未超支」是合法状态**（父子各自独立计算、互不扣减）；**超支不阻断录入**。
- 变更：**自下一期生效**，已结束当期按当时版本判定、永不追溯改写。

**⑧ 收益趋势（`trend`）**
- 核心信息：**收益曲线**（横轴刻度 = **交易日**，取自 `quote_daily` 的日期集合，**非交易日不补零不插值**）→ **收益率两口径并列表**（区间收益率 ÷ 期初持仓市值；累计收益率 ÷ 持仓成本合计）→ **已知不准**说明。
- 须显式标注：**持仓变动日的当日盈亏存在不可消除误差**（上界 = |Δ数量| × |当日每股涨跌额|），**如实标注而非剔除**。
- 须说明：区间收益 = 期末市值 − 期初市值（端点法权威）；**期初日自己的当日盈亏属于上一区间**。
- 多成员汇总：金额相加、**收益率按各自分母加权**（不可简单平均）。

**⑨ 除权确认（`ca`）**
- 核心信息：按 **(成员, 代码, 除权日)** 罗列的待确认事件，每条含方案原文（送转比例用万分比 / 派息用微元每股）+ 可采纳性徽标。
- 主操作：**采纳**（落新版本，生效日 = 除权日）/ **忽略**。
- 硬约束：「已忽略」**也是必须记住的决定**（否则同一建议会被反复提示）；采纳后可撤销（三步操作由触发器塌缩成一步）；**不做提前告知**（成员在除权日之前没有任何可执行的动作）。
- 状态徽标须区分「送转可采纳」与「分红仅提示」。

**⑩ 标签管理（`tags`）**
- 核心信息：类别树（两级，组可被打标签，标注「叶子 / 组 · 含 …」与引用笔数）→ 对象标签平铺列表 → 操作 → 模板包。
- 主操作：新建 / 改名（**只改当前基线**）/ **合并**（落「已并入」映射，**永不改写历史归属**）/ **归档**。
- 硬约束：默认集 5 个**完全不可变**（不可改不可删）；被历史引用的标签**删除会被 RESTRICT 拒绝**，只能归档；**标签归档 ⇒ 预算停用**；零引用删除 ⇒ 级联删除全部预算版本。

**⑪ 待同步（`queue`）**
- 核心信息：队列计数（N / 100）+ 逐条列表（标签 · 金额 · 发生时间 · 状态徽标 · **失败原因**）+ 协议说明。
- 硬约束：**不设过期**（这是用户的账，系统无权替他决定丢弃）；队列**属于设备，不属于会话**（登出、会话过期都不清空）；触发点 = App 启动 / `online` 事件 / 回到前台 + **30 秒节流**；整批一个请求、服务端逐条独立判定、**一条坏数据不阻塞其余**（预校验后才进事务）。

**⑫ 设置 / 我的（`me`）**
- 分区：我是谁（`GET /api/session`）→ 安装引导 → 标签与模板 → **会话** → 运行状态 → 关于。
- 会话分区必须含：**登出**（队列非空时提示「N 条待同步」，并说明**待同步记录会保留至下次登录**）+ **登出所有设备**（改密码由 DB 触发器强制触发同一效果，不由前端保证）。
- 关于分区须写明：**无注册页 · 无访客链接 · 无权限差异**（所有登录成员可见全部数据）。

### 3.3 为什么除权确认与待同步不合并（Q2 决议理由）

| 页面 | 若合并 | 否决理由 |
|---|---|---|
| `ca` 除权确认 | 并进 `stock` 的行情卡片流 | 除权建议是**待办**，不是行情附属。混在卡片流里，「有 3 条待确认」这类**需要用户行动**的状态不显眼，容易漏过 —— 而它一旦漏过，持仓数量就一直是错的。 |
| `queue` 待同步 | 改为底部抽屉 | 离线时用户最关心的是「刚记的账到底存上了没」。藏在抽屉里需要额外一步才能确认，且**失败原因**（如「类别已被归档，请重新选择」）没有稳定展示位。全局指示器只承担「有几条」的提示，**逐条诊断需要独立页面**。 |
| `assets` 资产（变体 B 产物） | — | **随 Q1 选 A 自动消失**，不是被否决，是失去存在理由（原型 `assets` 页自陈：「两个子系统在这一版里被收进同一个 Tab，靠分段控件切换」）。 |

## 4. 快速记账的最短路径

口径：**一次点击 = 1 步（不含键盘输入）；「保存」本身计 1 步。**

| 路径 | A 精剪（定型） | 说明 |
|---|---|---|
| 首页 → 记一笔 → 保存 | **2 步** | 最高频路径 |
| 记完 → 看流水 | **1 步** | 底栏相邻 Tab，无返回键开销 |
| 首页 → 股票 | **1 步** | 两个子系统各占一格 |
| 最坏路径 → 保存 | **3 步** | 从 `expense` 等二级页出发 |
| 首页 → 我的 | 2 步 | **本决议的代价**，见 §12 |

**表单内部不做多步向导**：金额、类别、对象、「谁花的」全部在**一屏内完成**（移动端视口内可滚动，但不分页）。理由：分步向导会为每笔多出 2–3 次点击，而本系统最高频的操作就是记账。

## 5. 桌面端策略（Q3 决议）

**同路由 + 宽屏响应式，不分叉。**

- 一套路由树、一套页面组件；宽屏（≥ 断点，实现期定）时切换为**左栏导航 + 多列内容**布局。
- 原型给出的唯一对照形态：左侧 172px 固定导航栏（列出全部 12 页）+ 右侧内容区由单列变多列。
- **桌面端不参与安装引导**（iOS 安装引导条只在非 standalone 的移动端出现；`beforeinstallprompt` 仅 Chromium 系有，Safari 完全没有，本期不做 Android / 桌面引导）。
- **被否选项：桌面独立路由分叉**（如 `/desktop/*`）。理由：高密度视图的收益主要来自**列数**，而响应式断点已经能给；分叉等于长期维护两套页面组件与两套状态，与「2 人自用」的规模不匹配。

**⚠️ 对 #12 的派生要求**：前端是 SPA + 客户端路由 ⇒ **部署侧必须有 catch-all fallback 到 `index.html`**，且 `_routes.json` 的 `exclude` 必须覆盖全部静态路径（否则每次页面加载的静态请求会吃掉 10 万/天额度）。此条与 #9 已交的 `_routes.json` 要求同向，此处补的是 **SPA fallback** 这一半。

## 6. 图表位置（Q4 决议）

**决议：分散放置。** 图表一律是**位置占位**，库选型与交互细节仍留雾区。

| 屏 | 图 | 形态 | 上游口径约束 |
|---|---|---|---|
| 首页 | 预算进度条 | 横向进度条 + **80% 阈值线 + 100% 超支线** | 家庭总预算口径 = 总支出；超支 = 消耗 > 上限（恰好等于不算） |
| 首页 | 类别 Top 5 | **横向条形**（非饼图） | Top-N 默认 5；按当前标签基线解释、实时聚合 |
| 支出分析 | 占比图 | 饼图 / 环图，**仅一层** | 类别轴或对象轴；对象维度重复计数为设计允许 |
| 支出分析 | 趋势折线 | 日度折线 | 分母 = **当期已过天数**（未结束期间只除已过天数） |
| 收益趋势 | 收益曲线 | 折线，**横轴刻度 = 交易日** | 取 `quote_daily` 的日期集合；**非交易日不补零、不插值** |
| 股票持仓 | **无图** | 纯表（当日盈亏 / 累计浮盈作列） | — |
| 预算 | 进度条（元件，非图表） | 每条预算一条 | 两档 80% / 100%，每条可覆盖阈值 |

**首页为何是条形而不是饼图**：首页要回答的是「哪几类花得多」，条形图的长度对比在拇指屏上比角度对比更快；占比的精确比较交给支出分析页的饼图。

**被否选项：图表全部集中到分析页，首页只留数字。** 否决理由：预算是本系统的**高频关注点**（每日记账时都要看还剩多少），把它降级成一串数字会失去「一眼看出快到线了」的能力。而页面对应的 `budget` 页虽然也有进度条，但需要多一步才能到达。

## 9. 全局元件（跨屏复用，不复刻）

三个条件渲染的横幅 + 一个指示器，**统一注入外壳，不在各页重复实现**：

2. **SW 更新横幅** —— 条件：SW 检测到新版本。队列非空时附带「（含 N 条待同步）」，文案**必须含「刷新不会丢失待同步记录」**。
3. **iOS 安装引导条** —— 条件：**已登录 + 非 standalone + 从未引导过**。检测以 `matchMedia('(display-mode: standalone)')` 为准，`navigator.standalone` 兜底。可关闭，**关闭后永久不再自动弹**（`me` 保留入口）。
4. **待同步指示器** —— 条件：`queue > 0`。显示「离线/在线」+「待同步 N 条 ›」，点击跳 `queue`。

## 10. 禁用清单

1. **不出现注册页或注册入口** —— `/api/register` 端点不存在，不是被禁用。
2. **不给只读访客 / 分享链接留任何位置**（#9 Q6 已定）。
3. **金额输入不用 `type="number"`**；**不用 `parseFloat(x) * 100`**。
4. **置灰不可只灰不说** —— 每个置灰入口必须内联原因。
5. **离线时不把队列项算进首页汇总** —— 复刻服务端聚合口径（子树合计、虚拟「未细分」行、「未指定对象」桶、CST 周期边界换算）就是**造第二个真相源**。宁可显示不完整但口径正确的数字 + 明确说明。
6. **不做服务端「定期消费」规则** —— 需新表 + cron，而 cron 配额只剩 1 个、要留给 #15 备份；用**本地模板**替代。
7. **不做标签自动补全输入框**（标签集只有几十个）。
8. **不做 Android / 桌面的安装引导**（Web 为辅）。
9. **不做多维矩阵分析**，分组轴恒为三选一。
10. **不用无条件 `skipWaiting()`** —— SW 更新走用户确认路径。
11. **不设队列过期丢弃**。
12. **运行状态卡不得把「上次成功运行」取全局最大**，必须按 `task` 分列。

## 12. 已知局限（如实标注）

1. **线框不证明交互正确。** `prototypes/11-frontend-ia.wireframe.html` 是低保真静态线框 + 状态开关，**没有真实交互、没有数据层、没有网络**。步数度量由**显式声明的导航图**经 BFS 算出，**依赖导航图的正确性**（本票自查中已修正一处：变体 D 的抽屉必须先开抽屉才能点条目，原图错建为「首页→记一笔 = 1 步」）。
2. **核验脚本只做关键字可见性扫描**，不做语义断言。某项要求「可见」不等于「正确」（例：文案出现 ≠ 该入口的行为正确）。
3. **桌面形态只给了一种对照形态**（左栏 + 多列），未穷举桌面布局方案；本票只定「同路由不分叉」这一条。
4. **未做真机验证**：线框在桌面浏览器中校验，未在 iOS Safari / PWA 独立窗口实测。iOS 安装引导条的触发条件、`matchMedia('(display-mode: standalone)')` 的实际取值**均未做真机验证**。
5. **页面上游口径的一致性由文本引用保证，非编译期保证** —— 本文件与 `CONTEXT.md`、三份契约之间没有机器校验，改动任一侧需人工比对。
