# 行情抓取与解析契约

> 本文件是**实现约定**，不是词汇表（词汇在仓库根 `CONTEXT.md`），也不是调研记录（调研在 `docs/research/`）。
> 凡本文件写明的口径，实现必须照此执行；凡本文件禁止的做法，实现不得自行放宽。
>
> **检索 / 实测口径日期：2026-09-15**（周二，交易日）。所有「实测」数据均于当日实际拉取取得。
> 决策依据：决策票 <https://github.com/Silencehuliang/FamilyAssetManagement/issues/13>（行情抓取与落库架构）。
> 可复跑验证：`docs/verification/quote-fetch-probe.py` / `.out.txt`。

---

## 0. 一句话总纲

**每日 CST 15:30 由独立 Cron Worker 触发一次；先合并抓一次行情、再查一次当日除权名单；两件事各写各的、各记各的成败；心跳独立落库。**

---

## 1. 触发与运行模型

| 项 | 约定 |
|---|---|
| Cron 表达式 | `30 7 * * MON-FRI`（UTC）＝ CST 15:30，周一至周五 |
| 账户级 Cron 配额 | **仅此 1 个**。补数、回填**不得新增 cron**，一律并入本次运行或由前端手动触发 |
| 目标交易日 | 运行时刻按 Asia/Shanghai 换算出的 `YYYY-MM-DD` |
| 墙钟上限 | 15 分钟（Cron 硬上限）；CPU 上限 10ms（**不含 I/O 等待**） |
| `ctx.waitUntil` | 仅用于收尾/登记；不得用于跨小时补发 |
| 重试 | **同一次运行内不重试**。失败由「次日自愈 + 前端手动补数」兜底 |
| 并发 | **串行发起**。平台规定同一 invocation 内同时「等响应头」的连接 ≤ 6 |

**抓取范围**：运行时刻按持仓版本核算出的「持仓数量 > 0」的股票集合（`sh` / `sz` 六位码）。
持仓当天 16:00 才补录的股票会错过本次，**由次日自愈补上前一日缺口** —— 不为此引入「每日重抓前一日」。

## 2. 源分工与降级链

```
腾讯 qt.gtimg.cn（主，GBK）
  └─ 失败/陈旧 ──> 新浪 hq.sinajs.cn（备，GBK，必须带 Referer）
       └─ 失败/陈旧 ──> 东财 push2his kline（当日行，UTF-8）
            └─ 全失败 ──> 标记「当日市值待录入」，等成员手工录入（终降级）
```

**降级仅在「整批」层面发生**：某一源被判失败后，整批改由下一源承担；但**同一源内某只代码解析失败只跳过该只**，不整批判失败（逐股失败隔离）。

## 3. 字段契约

### 3.1 腾讯实时（主源）

```
GET https://qt.gtimg.cn/q=sh600519,sz000001    ← 逗号合并，一次拉全部持仓
编码：GBK    分隔：~    行形如  v_sh600519="...";
```

| 下标 | 含义 |
|---|---|
| 0 | 市场标识（实测沪市 = `1`） |
| 1 | **名称**（除权日带 `XD`/`XR`/`DR` 前缀） |
| 2 | 代码 |
| **3** | **最新价（元）** |
| **4** | **昨收（元）** |
| 5 | 今开 |
| 6 | 成交量（手） |
| 30 | **时间 `YYYYMMDDHHMMSS`**（如 `20260915161438`） |
| 31 | 涨跌额 |
| 32 | 涨跌幅 % |
| 33 / 34 | 最高 / 最低 |

**实测样本（2026-09-15，除权日）**：
`v_sh603929="1~XD亚翔集~603929~152.71~150.56~150.00~...~20260915161438~2.15~1.43~156.96~149.50~..."`
⇒ 最新价 152.71、**昨收 150.56**、今开 150.00、涨跌额 2.15、涨跌幅 1.43%。

### 3.2 新浪实时（备源）

```
GET https://hq.sinajs.cn/list=sh600519,sz000001
必须带请求头：Referer: https://finance.sina.com.cn    ← 否则 403 / "Kinsoku jikou desu!"
编码：GBK    分隔：,    行形如  var hq_str_sh600519="...";
```

| 下标 | 含义 |
|---|---|
| 0 | **名称**（除权日带 `XD`/`XR`/`DR` 前缀） |
| 1 | 今开 |
| **2** | **昨收** |
| **3** | **最新价** |
| 4 / 5 | 最高 / 最低 |
| 6 / 7 | 买一 / 卖一 |
| 8 / 9 | 成交量（股）/ 成交额（元） |
| 10–29 | 五档买卖盘 |
| 30 | **日期 `YYYY-MM-DD`** |
| 31 | 时间 `HH:MM:SS` |
| 32 | 状态码（实测 `00`，枚举未文档化） |

**实测样本（2026-09-15，除权日）**：
`var hq_str_sh603929="XD亚翔集,150.000,150.560,152.710,156.960,149.500,...,2026-09-15,15:34:59,00,D|1900|290149.00";`
⇒ 今开 150.000、**昨收 150.560**、最新价 152.710。

> ⚠️ **新浪的价格是 3 位小数**，A 股股票最小变动单位为 0.01 元 ⇒ 第 3 位小数应恒为 0。
> 出现非 0（如 `152.715`）说明口径异常 ⇒ **记 warn 并拒绝该行**，不得静默取整。

### 3.3 东财历史（第三源 / 回填源）

```
GET https://push2his.eastmoney.com/api/qt/stock/kline/get
      ?secid=1.600519          ← 沪市 1.代码 / 深市 0.代码
      &fields1=f1,f2,f3,f4,f5,f6
      &fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
      &klt=101                 ← 日线
      &fqt=0                   ← 0 不复权（存储口径）/ 1 前复权（仅用于差分，见 §6）
      &beg=0&end=20500101      ← 一次返回全部历史
编码：UTF-8 JSON
```

| 字段 | 含义 |
|---|---|
| `f51` | 日期 `YYYY-MM-DD` |
| `f52` / `f53` | 开 / **收** |
| `f54` / `f55` | 高 / 低 |
| `f56` / `f57` | 量 / 额 |
| `f58` | 振幅 % |
| `f59` | 涨跌幅 % |
| `f60` | 涨跌额 |
| `f61` | 换手率 % |
| `data.preKPrice` | 窗口首根 K 线的**前一日收盘**（随 `fqt` 切换） |
| `data.dktotal` | 该股日线总根数（实测 sh600519 = 6005，≈24.6 年） |

> **一次请求返回全部历史**：`beg`/`end` 只是参数，回填成本**只与股票只数成正比，与回填深度无关**。

### 3.4 东财分红送转（除权检测）

```
GET https://datacenter-web.eastmoney.com/api/data/v1/get
      ?reportName=RPT_SHAREBONUS_DET&columns=ALL&pageSize=100
      &filter=(EX_DIVIDEND_DATE>='2026-09-15')(EX_DIVIDEND_DATE<='2026-09-15')
      &sortColumns=EX_DIVIDEND_DATE&sortTypes=-1
编码：UTF-8 JSON，记录在 result.data[]
```

**三种过滤形态（均实测可用）**：

| 形态 | filter 写法 | 用途 |
|---|---|---|
| 单码全历史 | `(SECURITY_CODE="600519")` | 回溯某只股的全部除权事件（实测回溯至 2002 年） |
| 多码 | `(SECURITY_CODE in ("600519","000001"))` | 少量代码时 |
| **日期区间** | `(EX_DIVIDEND_DATE>='D')(EX_DIVIDEND_DATE<='D')` | **日常检测用这个 —— N 只股票只需 1 个请求** |

| 字段 | 用法 |
|---|---|
| `SECURITY_CODE` | 六位码 → 规范化时需自行补 `sh`/`sz` 前缀 |
| `EX_DIVIDEND_DATE` | 除权除息日（`YYYY-MM-DD 00:00:00`）→ **采纳后新持仓版本的生效日** |
| `EQUITY_RECORD_DATE` | 股权登记日 |
| `PRETAX_BONUS_RMB` | **每 10 股含税派息（元）** |
| `IMPL_PLAN_PROFILE` | 方案原文（如 `10送1.00派43.74元(含税,扣税后39.266元)`） |
| `BONUS_IT_RATIO` / `BONUS_RATIO` / `IT_RATIO` | **实测为 `null`** ⇒ 送转比例只能从 `IMPL_PLAN_PROFILE` 解析 |
| `ASSIGN_PROGRESS` | 实测 `实施分配` |

## 4. 编码

| 源 | 编码 | 解法 |
|---|---|---|
| 腾讯 | GBK | `new TextDecoder("gbk").decode(bytes)` |
| 新浪 | GBK | 同上 |
| 东财 | UTF-8 | `await res.json()` |

**Worker 的 `compatibility_date` 必须 ≥ `2026-03-03`**（该日起 `text_decoder_cjk_decoder` 默认开启）。

> ⚠️ **上线前硬门禁**：Cloudflare 的 Encoding 文档页至今仍把 `TextDecoder` 描述为 *"represents a UTF-8 decoder"*，
> GBK 能力只有**间接官方依据**（兼容性标志的存在与描述）。**主源与备源都是 GBK**，所以这条必须在构建期实测证伪：
> 真实 fetch 一次 `qt.gtimg.cn`，用 `new TextDecoder("gbk")` 解码，**断言中文简称不是乱码**。
> 若证伪，退路是把东财实时 `push2`（UTF-8 JSON）插为第二源。

## 5. 失败判据（六条，任一命中即降级）

1. **HTTP 状态非 2xx**（含重定向链耗尽）
2. **超时** —— 自管 `AbortSignal.timeout(5000)`。
   ⚠️ 官方明确「**子请求没有时间上限**」，不设超时的话源站挂起会一路占到 cron 的 15 分钟墙钟。
3. **解码失败**（GBK / UTF-8 抛错）
4. **字段数不足**（腾讯 `< 33` 段、新浪 `< 33` 段、东财缺 `f51`/`f53`）
5. **`最新价 <= 0`** —— 盘后/休市时源可能返回 0，**不得当成价格 0 入库**（一根假 0 会让整只股票变成 −100%）
6. **返回日期 ≠ 目标交易日**（腾讯取 f30 前 8 位、新浪取 f30、东财取 f51）

**`prev_close` 另有独立判据**：**`prev_close <= 0` 同样判为无效**。
理由：单日窗口 `preKPrice` 在非交易日会返回 `0.0`（实测），而 `0.0` **结构合法、类型正确**，
会穿过所有「非空 / 可解析」的校验 —— 与「最新价 == 0」是同一类陷阱，必须同样设防。

**空字段处理**：腾讯返回中以 `~~` 表示空值。**空字符串不得被 `parseFloat` 静默转成 `NaN` 后当 0 用**，
应显式判为「字段缺失」并计入判据 4。

## 6. 价格解析

### 6.1 元 → 分

A 股股票价格以 `0.01` 元为最小变动单位，库内一律存**整数「分」**。

```js
// 正确
const cents = Math.round(parseFloat(s) * 100);
// 错误 —— 截断会在浮点误差上出错
const bad = Math.trunc(parseFloat(s) * 100);
```

**实测**（`quote-fetch-probe.py` §6，7 个样例中 **3 个** `int()` 与 `round()` 结果不同）：
`1.150 → 114.99999999999999`（int 得 114，应为 115）、
`0.290 → 28.999999999999996`（int 得 28，应为 29）、
`1212.100 → 121209.99999999999`（int 得 121209，应为 121210）。

### 6.2 派息金额 → 微元

`PRETAX_BONUS_RMB` 是**每 10 股含税派息（元）**：

```
cash_per_share_micro = Math.round(PRETAX_BONUS_RMB * 100000)
```

实测茅台 `280.2423` ⇒ `28024230` 微元 = **28.02423 元/股**（5 位小数）。
**分（2 位）与厘（3 位）都会失真，必须用微元。**

### 6.3 送转比例 → 万分比

从 `IMPL_PLAN_PROFILE` 解析：匹配 `10(送|转)(\d+(\.\d+)?)`，多个片段（`10送1转2`）**求和**。

```
bonus_ratio_ppm = Math.round(每10股送转股数 × 1000)
```

`10送1` → `1000`（= 0.1）；`10送3` → `3000`；`10转10` → `10000`；`10送1转2` → `3000`。

## 7. 日期与交易日

**系统不自建、也不维护交易日历。** 交易日序列由**行情源返回的日期序列**定义。

| 情形 | 证据 | 结果 |
|---|---|---|
| 抓到目标交易日的行情 | 源返回的日期 == 目标交易日 | `ok` |
| **非交易日**（法定节假日 / 周末） | **至少一个源给出了结构合法、但日期是上一个交易日的响应** | **`skipped`** |
| **故障** | 无响应 / 超时 / 解码失败 / 字段不足 / 价格 ≤ 0 | `failed` |

**关键区分**：`skipped` 不是「猜今天是不是交易日」，而是「**源是否给出了一个明确的日期否定**」——
前者是猜测，后者是事实。

**信号冲突的处理**：若主源超时、备源返回旧日期，判 **`skipped` 结案，但把主源超时写进心跳的 error 字段**
（这样真出问题时会以「连续 error」的形式浮出来，而不是被静默吞掉）。

## 8. 除权检测契约

1. 用**日期区间过滤**拉「目标交易日全市场除权名单」，与持仓求交。
2. **必须丢弃 `EX_DIVIDEND_DATE` 为 null 的记录**（实测返回中含分红**预案**，其 ex-date 与金额均为 null）。
3. **不得假设返回的代码都是 `sh`/`sz`** —— 实测含北交所代码（如 `920663.BJ`）。
   与持仓求交天然排除，但解析层不得依赖这一点。
4. 区间过滤会返回**尚未实施的未来除权日**（实测查到 2026-09-22）。
   **本票决定不做提前告知**，故检测窗口取「`EX_DIVIDEND_DATE` == 目标交易日」当天即可。
5. 检测结果写入 `corporate_action`，`status = 'pending'`。

### 8.1 「过滤 null」与「唯一约束」缺一不可

实测（同一批 5 条有效 + 1 条预案，连跑 2 次）：

| 建表方式 | 行数 | 结论 |
|---|---|---|
| 裸表，无唯一约束 | 12 | 每条各插一次 ⇒ 全面增殖 |
| 唯一约束，但不过滤 null | **7** | 5 条有效被去重，**NULL 那条第 2 次仍插入** |
| 过滤 null + `(member_id, code, ex_date)` 唯一 | **5** | 幂等 ✓ |

**SQLite 的唯一约束对 NULL 完全无效**（NULL 不参与唯一性比较）——
只加唯一键挡不住预案记录，只过滤 null 而不加唯一键则所有记录都会增殖。

### 8.2 `XD` / `XR` / `DR` 简称前缀（零成本二次确认）

除权日证券简称会带前缀，实测三处一致：腾讯字段 1 / 新浪字段 0 / 东财 kline 的 `name` 均为 `XD亚翔集`。

- **用途**：当 RPT 的当日名单尚未更新时作为**兜底检出**；以及作为**交叉校验**
  （RPT 说当日除权但简称无前缀 ⇒ 记 warn）。
- **限制**：前缀只说明「当日除权」这一事实，**给不出方案**（派息金额 / 送转比例），
  因此**只能用于「检出并提示成员手工核对」，不得用于生成持仓调整建议**。
- **标注**：这是**实测 + 沪深市场惯例**，本文件不宣称已核验交易所规则原文。

## 9. 回填契约

### 9.1 缺口来源：事件触发，不盲扫

缺口的真实来源只有两个，**都不需要每日扫描**：

1. **抓取失败** → 由**心跳表**可知（上一次运行 `result != 'ok'` 的日期集合）
2. **补录了更早生效的持仓版本** → 由**持仓版本写入这个动作**可知

⇒ **自愈只在「上一次运行非 ok」时触发**；**补录版本时当场触发一次该股该区间的回填**（走 Pages Functions，不计入 cron 预算）。

### 9.2 `close` 与 `prev_close` 分开取

| 项 | 请求数 | 做法 |
|---|---|---|
| `close` | 1 / 股 | `fqt=0` 全量序列，直接取 `f53` |
| `prev_close` | 1 / 股 | 拉 `fqt=1` 全量序列，用**差分修正**（下） |

**差分修正公式**：

```
prev_close(D) = fqt0(D) − [ fqt1(D) − fqt1(D_prev) ]
```

其中 `D_prev` 是 `D` 的前一个**交易日**（取自 `fqt=0` 序列的前一行）。

**实测精度**：

| 情形 | 结果 |
|---|---|
| 茅台 2026-06-26（其后无除权） | `1168.63 − (1168.63 − 1184.08)` = **1184.08** ✓ 精确 |
| 茅台 2025-12-19（其后有 2026-06-26） | `1410.00 − (1381.98 − 1379.02)` = **1407.04** ✓ 精确 |
| 茅台 2015-07-17（送转日） | `228.29 − (−69.47 − (−73.01))` = **224.75** vs 真值 224.74（1 分内） |

**精度边界（必须配白名单校验）**：

- 差分修正**只在「其后无送转事件」的区间精确**。跨送转时序列被 `1/Π(1+r)` 缩放。
  实测茅台 2015 年送转日**之前**的区间：fqt 差分 / 真实涨跌 = `0.9095` ≈ `1/1.1`。
- **校验规则**：以 `corporate_action` 为白名单 —— **非除权日算出的 `prev_close` 必须等于 `fqt0(D_prev)`**；
  不等即判该日 `prev_close` **置 NULL，不填错值**。
  实测：`2025-12-17` 通过（1422.00 = 1422.00）；`2015-07-15` 不通过（差 0.20 元）⇒ 置 NULL。
- **`fqt=1` 序列对长历史会出负值**（实测茅台 2015 年为 ≈ −70 元）⇒ **只能取差分，绝不能当价格用**。

**`prev_close` 允许为 NULL**：该日**当日浮动盈亏标「不可得」**；
区间收益（端点法）、持仓市值、累计浮动盈亏**不受影响**。

## 10. 禁用清单

以下做法**在实现中一律禁止**：

| # | 禁止 | 理由 |
|---|---|---|
| 1 | 用本地收盘序列（`fqt0` 的前一日）作 `prev_close` | 除权日会凭空造出假暴跌，实测差 1.65 元/股 |
| 2 | 用 kline 的 `f60`/`f59` 反推昨收 | 同一接口对不同除权日采用不同基准，机制未查明 |
| 3 | 用单日窗口 `preKPrice`（`beg=end=D`）回填昨收 | 非交易日返回 `0.0`，且 0.0 会伪装成合法值 |
| 4 | 把 `fqt=1` 序列逐日抓取后冻结入库 | 基准锚在拉取当日，逐行冻结不同基准 |
| 5 | 不给 `fetch` 设超时 | 官方明确子请求无时间上限，会占满 15 分钟墙钟 |
| 6 | 把心跳记录放进数据 `batch()` | **`batch()` 是原子事务，失败会连心跳一起回滚** —— 最需要它时把它抹掉 |
| 7 | 新增任何 cron | 账户级配额 5 个仅余 1，已留给 #13/#15 的取舍 |
| 8 | 用 `int()` / `trunc` 把元转分 | 实测 3/7 样例出错 |
| 9 | 假设 RPT 返回的都是 `sh`/`sz` | 实测含北交所代码 |
| 10 | 把 `0` 或空字符串当价格入库 | 假 0 会让整只股票变成 −100% |
| 11 | 为每只持仓股逐股发 `fetch` | 必须逗号合并；50 只逐股发就吃掉全部子请求预算 |
| 12 | 把持仓股逐只丢进 `fqt=1` 的全量拉取以「顺便」拿昨收 | 见第 1/4 条 —— 昨收必须先过白名单校验 |

## 11. 写入契约

### 11.1 事务边界

```
try {
  batch A: quote_daily   ← 行情
  batch B: corporate_action ← 除权检测
} finally {
  单条 INSERT: run_heartbeat   ← 无论成败都落库
}
```

**心跳与数据彻底分离**。理由：`D1.batch()` 是原子事务，任一条失败则整体回滚 ——
若心跳在同一批里，数据写入失败时心跳会被一并回滚，**恰好在我们最需要它的时候把它抹掉**。

行情与除权拆成两次独立 batch：行情成功但分红接口挂着时，当天行情照样落库，
心跳如实写「行情 ok / 除权 failed」——失败被隔离在它真正发生的那一半。

### 11.2 来源优先级与覆盖规则

```
manual(0) < backfill(1) < feed(2)
```

`INSERT ... ON CONFLICT(code, trade_date) DO UPDATE`，**仅当新来源 rank > 已有 rank 时覆盖**。

- 权威源可覆盖手工行（#8 的刻意不对称：手填的持仓不可擅改，手填的兜底行情可被权威源覆盖）
- **同级不覆盖** —— 同日重复运行保持幂等
- `feed` 不会被 `backfill` 覆盖（feed 那行带着当时的实时昨收，是更权威的点事实）

### 11.3 用量

D1 免费版日写配额 **10 万行/天，按实际写入行数计**；
**建有索引的列写入时每行额外产生 1 行索引写入**（行数翻倍计）。
持仓 20–50 只 ⇒ 数十行/天，与配额相距三个数量级。

D1 调用计入**内部服务子请求（1,000/invocation）**，与外部子请求的 **50** 是两套额度。

## 14. 已知局限（如实列出，不掩盖）

1. **历史昨收不可重建**（除 §9.2 的窄口径外）。
   `fqt=1` 只在「其后无除权/无送转」时有效，`f60` 口径矛盾，`preKPrice` 非交易日返回 0。
   ⇒ **行情表不是「可从外部重抓的缓存」，而是唯一副本**，必须纳入备份（见 §15）。
2. **平台事实建立在间接官方依据上**：GBK 能力只有兼容性标志的存在与描述作支撑（§4）。
3. **`f60` 口径矛盾的机制未查明**（§10 第 2 条）。本文只据实测结果禁用，不解释成因。
4. **`XD` 前缀未核交易所规则原文**（§8.2）。
5. **手动补数若超出单次上限，需要分多次点** —— 界面必须如实提示「本次补了 N 只，剩余 M 只请再点一次」，
   **不得静默截断**。

## 15. 给下游票的派生要求

**→ «D1 schema 与索引定稿»（#14）**

1. `corporate_action` 增列 **`applied_version_id`**（nullable，指向采纳时生成的持仓版本），以支持撤销。
2. 运行心跳表需容纳 `result ∈ {ok, skipped, failed}` 与 `error` 摘要。
3. **不建任何行情相关的汇总表或缓存表。**

**→ «备份与导出策略»（#15）**

4. **`quote_daily` 与 `corporate_action` 必须纳入备份。**
   依据：§14.1 —— 历史昨收不可重建，每只股票只能回填一次，行情表是唯一副本。
   **若只备份支出与持仓而丢掉行情表，历史收益曲线将永久不可复原。**

**→ «前端信息架构与页面清单»（#11）**

5. 需要一处**缺口提示条**：「补数」（服务器此刻若连得上东财，一键补齐 `close` + `prev_close`）在前，
   「手工录入收盘价」（只问一个数、不问昨收）在其后。
6. 需要一处**连续失败横幅**：「行情已连续 N 日未更新（最近成功：YYYY-MM-DD）」。
